# Доступ к закрытому боту

`TELEGRAM_ALLOWED_USER_IDS` содержит только владельцев-администраторов. Одобрение
пользователя не меняет эту настройку и не делает пользователя администратором.

Новый пользователь отправляет `/start`. Бот сохраняет заявку со статусом
`pending`, но не открывает поиск, подписки и историю цен. Повторный `/start`
не сбрасывает отказ владельца.

Владелец открывает `/requests` в личном чате с ботом и выбирает «Одобрить» или
«Отказать». `/approved` показывает одобренных пользователей с кнопками отзыва.
Команда `/deny ID` отзывает доступ, `/approve ID` позволяет изменить прежнее
решение. Решение сохраняется в `telegram_access_requests` вместе со временем
и ID владельца. В списках показано до 20 записей; после обработки заявок
вызови команду повторно. Владельцев из настройки отозвать этими командами нельзя.

После решения пользователь сам нажимает «Проверить решение» на экране ожидающей
заявки, повторно открывает приложение или отправляет `/start`. Автоматическое
сообщение о решении ему не отправляется. Одобрение
само по себе не включает уведомления: для них нужен `/start`. `/stop` отключает
уведомления и сохраняет одобрение и подписки.

Оболочка `/app` и статические файлы открываются без входа, но поиск и навигация
остаются закрыты до подтверждения доступа. В обычном браузере анонимного поиска
нет. Даже списки стран и питания загружаются через защищённый `/api/options`.
Все API с турами и личными данными проверяют подписанные Telegram `initData`
из заголовка `X-Telegram-Init-Data` и текущее одобрение. Отсутствующая или
недействительная сессия даёт `401`; приложение предлагает открыть его заново
через бота. Ответ `403` имеет вид
`{"detail":{"code":"access_required","access_state":"pending"}}`; возможны
также `denied` и `not_requested`. Поле `message` содержит текст для пользователя.
Сессия владельца имеет `is_owner: true` и `is_admin: true`. Если база недоступна,
владелец сохраняет аутентификацию, но `can_notify` возвращается как `false`;
остальные пользователи получают `503`, пока одобрение невозможно проверить.

Обработчик уведомлений заново проверяет разрешение при захвате каждого алерта.
Отзыв блокирует будущие отправки; уже выполняющийся запрос Telegram отозвать
невозможно. Неотправленные алерты отозванного пользователя не отправляются.

При первоначальной настройке этого механизма запусти `Prepare Telegram database`: сначала `preflight`, затем
`apply`, оставив `build_index=false`. Это добавит таблицу заявок и небольшой
индекс без удаления данных. Затем повторно выполни настройку бота
`python -m tourfinder.telegram_bot configure`, чтобы webhook принимал
`callback_query` и появились команды `/requests`, `/approved`, `/deny`.

Локальное демо включается только сочетанием `TOURFINDER_DEMO=1`, отсутствующего
токена бота и SQLite вне Vercel. Оно разрешает чтение туров и не разрешает
личные записи. В production демо не открывает доступ к данным.
