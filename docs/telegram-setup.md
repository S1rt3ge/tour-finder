# Telegram: личный бот и Mini App

Бот уже создан и настроен; production Mini App доступен по адресу
<https://tour-finder-rose.vercel.app/app>. Поиск закрыт до входа через Telegram
и одобрения владельцем. Ниже описаны действующее поведение и настройка нового
окружения; повторно создавать существующего бота не нужно. Доставка подходящего
алерта проверяется отдельно от запуска интерфейса и настройки webhook.

## Что уже реализовано

- `/app`: поиск из Риги, точный состав с возрастами детей, фильтры, варианты
  номеров, просмотр предложения внутри приложения, история цен, недавние
  падения, личные сохранённые поиски. Категории питания можно выбирать вместе;
  точные обозначения оператора доступны в дополнительном фильтре.
- Бот: `/start`, `/app`, `/stop`, `/id`; владельцу — `/requests`, `/approved`,
  `/approve ID`, `/deny ID`. В меню чата есть кнопка приложения.
- Сервер проверяет подпись Telegram `initData`, давность до часа и текущее
  разрешение. `TELEGRAM_ALLOWED_USER_IDS` задаёт владельцев-администраторов;
  остальные пользователи получают доступ после решения владельца в боте.
  В обычном браузере открывается только оболочка с экраном входа. Поиск,
  фильтры из API, предложения, история и личные данные требуют одобрения.
  Порядок выдачи доступа описан в [telegram-access.md](telegram-access.md).
- Если нужный точный состав ещё не собран, одобренный пользователь может
  явно добавить его в очередь сбора. Цены другого состава не подставляются.
- Уведомления накапливаются в БД. Worker отправляет их независимо от открытой
  вкладки; `/stop` останавливает доставку, сохраняя поиски.

## Как определяется выгода

В каждом поиске доступны три режима: подтверждённое падение цены, попадание в
бюджет, либо оба. Бюджет — цена всего тура за весь указанный состав, в евро.
Попадание в бюджет само по себе не называется скидкой.

По умолчанию для подтверждённой выгоды нужны одновременно:

1. Падение от 10% **и** экономия от €100 относительно последней отличающейся
   цены того же предложения, номера, питания, даты и состава.
2. Старая цена наблюдалась минимум дважды с интервалом от 6 часов. Проверяется
   непрерывная серия одинаковой цены, а не рекламная зачёркнутая цена источника.
3. Первый снимок новой низкой цены — не старше 72 часов; повторный такой же
   снимок не продлевает этот срок.
4. Подтверждённое сопоставление отеля с отзывами, рейтинг от 4/5 и от 20 отзывов.
5. Последняя цена не старше 6 часов, вылет не прошёл, валюта EUR, нет stop-sale.

Порог процента, суммы и отзывов можно изменить при сохранении поиска. Для
сравнения читаются последние 14 дней и последняя точка перед этим окном — она
сохраняет смысл истории после схлопывания одинаковых наблюдений. Среднее по
прореженной истории не используется как основание для скидки.

Для исторического сигнала Waavo допускаются только новые идентичности
`room_code`, точно соответствующие `wv2:[0-9a-f]{64}`. Они учитывают ключ
источника, номер и питание, оператора, отель, даты, длительность, аэропорты,
трансфер, валюту и подтверждённый состав. Цена и рекламная «старая цена» в этот
ключ не входят. Все перечисленные выше требования к выгоде сохраняются.

Пустые старые ключи и неполные идентичности `wu2:` не дают исторических сигналов
в режимах «выгода» и «оба». Обычный поиск и честные сигналы бюджета остаются
доступны; в режиме «оба» неподтверждённая скидка может дать только совпадение с
бюджетом. Старая история не переносится в новые ключи. Для `wv2:` сначала нужно
накопить собственную устойчивую прежнюю цену. Если Waavo меняет `offerKey`
вместе с ценой, сравнение будет пропущено, а не восстановлено догадкой.

Каждая оценка проверяет до 500 предложений подписки и сохраняет позицию следующей
страницы; большой поиск обходится за несколько запусков. Изменение сортировки
цен между запусками может сдвигать страницы. Это ограниченный периодический
мониторинг, а не гарантия мгновенного обнаружения всех предложений.

Доставка ограничена тремя сообщениями в скользящие 24 часа на пользователя и
одним отелем по подписке за 24 часа. Неотправленные события старше суток
устаревают. При неопределённом сетевом результате запись становится `uncertain`:
автоматического повтора нет, поскольку Telegram мог уже принять сообщение.
Такие случаи нужно просмотреть отдельно; полная exactly-once доставка через
Bot API не гарантируется.

## Создать нового бота

Этот раздел нужен только для отдельного нового бота или нового окружения.

1. Открой официального [@BotFather](https://t.me/BotFather), введи `/newbot`,
   выбери название и свободный username, заканчивающийся на `bot`.
2. Сохрани токен локально в `data/telegram.env`, скопировав структуру из
   `config/telegram.env.example`. Токен не нужно присылать в чат или коммитить.
3. `TELEGRAM_BOT_USERNAME` — username без `@`. `TELEGRAM_WEBHOOK_SECRET` —
   отдельная случайная строка; можно сгенерировать локально командой
   `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
4. ID можно узнать через команду `/id` у собственного бота после установки
   webhook. Затем внеси ID владельца в `TELEGRAM_ALLOWED_USER_IDS` на серверах
   и снова отправь `/start`. Пока владельцы не настроены, доступ к приложению
   закрыт. Обычных пользователей добавляй через `/requests`, а не в переменную
   с владельцами.

## Настройки серверов

Vercel Environment Variables (server-side, **без** префикса `NEXT_PUBLIC_`):

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | Уже используемый Supabase connection string |
| `TELEGRAM_BOT_TOKEN` | Секрет из BotFather |
| `TELEGRAM_BOT_USERNAME` | Username без `@` |
| `TELEGRAM_WEBHOOK_SECRET` | Случайная строка 32–256 символов `A-Z a-z 0-9 _ -` |
| `TELEGRAM_ALLOWED_USER_IDS` | ID владельцев-администраторов; несколько — через запятую |
| `TELEGRAM_APP_URL` | `https://tour-finder-rose.vercel.app/app` |

GitHub Actions Secrets: `DATABASE_URL`, `TELEGRAM_BOT_TOKEN`,
`TELEGRAM_ALLOWED_USER_IDS`. Repository Variable `TELEGRAM_APP_URL` задаёт
публичный HTTPS адрес приложения (по умолчанию адрес выше).
Username и webhook secret для worker не нужны.

## Настройка окружения и проверка

1. Убедиться, что архив доступен и восстановление проверено. Перед применением
   к заполненной Supabase оценить свободное место: новый индекс требует места,
   архив сам по себе его не освобождает. Очистка старых данных — отдельная
   операция, которую настройка Telegram не запускает.
2. Для обновления существующей Supabase использовать workflow
   [`Prepare Telegram database`](../.github/workflows/prepare-telegram.yml):
   сначала `preflight`, затем `apply` с `build_index=false`. Он добавляет
   необходимые поля, Telegram-таблицы и таблицу заявок без удаления данных.
   Большой индекс истории включается отдельно через `build_index=true` после
   оценки свободного места; он строится `CONCURRENTLY`. Не запускать несколько
   миграций параллельно. Обычный `create_all` не обновляет существующую схему.
3. Развернуть код на Vercel с переменными выше. `/` перенаправляет в `/app`.
   Не включать `TOURFINDER_DEMO` в production.
4. С локальным файлом настроек выполнить:

   ```powershell
   python -m tourfinder.telegram_bot configure --env-file data/telegram.env
   ```

   Команда проверит бота, настроит команды, кнопку приложения и webhook с
   секретом для `message` и `callback_query`. Она не очищает очередь Telegram.
   При изменении переменных Vercel требуется новый deployment.
5. Владелец отправляет `/start` и открывает приложение. Новый пользователь
   сначала отправляет `/start`; владелец одобряет заявку через `/requests`.
   Затем пользователь повторяет `/start` для включения уведомлений и сохраняет поиск. Проверить
   сначала `python -m tourfinder.telegram_delivery --dry-run`
   в окружении с нужными переменными. Dry-run не оценивает новые подписки, не
   меняет БД и не отправляет сообщений; показывает уже накопленную очередь.
6. Workflow [`notify.yml`](../.github/workflows/notify.yml) запускает оценку и
   доставку примерно каждые 15 минут, после завершения `collect` из `main` этого
   репозитория и по ручному запуску. Без токена, владельцев или DB job пропускается.
   GitHub cron может задерживаться. Успешный run без кандидатов не подтверждает
   отправку сообщения: доставка проверяется по очереди, результату worker и чату.

Ноль кандидатов не требует снижать пороги качества. Проверь свежесть сбора для
нужных source/tier/pax, точность состава, действующие даты поиска, подтверждённые
отзывы и наличие достаточной истории одного ключа. В частности, новые `wv2:`
не получают старую историю Waavo автоматически.

Официальные протоколы: [Mini Apps и проверка initData](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app),
[Bot API](https://core.telegram.org/bots/api).

## Локальная проверка

```powershell
python -m pip install -e '.[dev]'
python -m pytest -q
python -m uvicorn tourfinder.webapp:app --host 127.0.0.1 --port 8000 --env-file data/telegram.env
```

Тесты используют временные SQLite-базы и подставной Telegram client. Они не
открывают пользовательский `data/tourfinder.db`, production Supabase и не
отправляют Telegram-сообщения. PostgreSQL-планы и реальный Telegram WebView
проверяются отдельно при запуске. При работе с данной Windows-копией готовое
окружение находится в `data/.venv-codex` (старый `.venv` ссылается на другой ПК).

Обычный локальный запуск также требует одобренную Telegram-сессию. Для проверки
интерфейса без неё допустимо только локальное демо: `TOURFINDER_DEMO=1`, отсутствие
токена бота, SQLite и отсутствие окружения Vercel. Оно разрешает чтение тестовых
туров, но не личные записи. Флаг не открывает production-доступ.

## Следующие улучшения

1. Проверить индексы и задержку запросов на production после безопасного
   освобождения места; измерить свежесть отдельно для source/tier/pax.
2. Накопить наблюдения новых ключей Waavo и проверить стабильность `offerKey`
   между сборами. Восстановление пагинации сборщика с места остановки остаётся
   отдельным улучшением: дедлайн кооперативный, незаконченный обход остаётся
   просроченным и уступает очередь другим заданиям.
3. Обучение на архиве: временной train/test split, одинаковый оффер, отдельные
   признаки по источникам; сначала backtest точности уведомлений. Рекомендацию
   «покупать или ждать» включать только после сравнения с простой базовой
   стратегией. В этой версии прогнозов нет.
